# boatrace-yosou

競艇(3連単)の期待値予想システム。目的は **回収率100%超え** の検証と、毎日の予想の配信。

## 考え方
- 舟券の払戻率は約75%(実データで、オッズから逆算した確率の合計は約1.34)。当てるだけでは儲からない。
- 必要なのは「市場(オッズ)より正確な確率」。そこで次の3段階にしている。
  1. LightGBMで各艇の1着しやすさを推定する(番組表・選手の過去成績・コース別成績・モーター・展示タイム・気象)
  2. Harville＋着順ごとの温度補正で、3連単120通りの確率に変換する
  3. 市場確率とブレンドする: `log p = a·log p_model + b·log p_market`。
     a≈0なら、モデルは市場以上の情報を持っていない=儲からない、と判定できる
- 期待値 = p × オッズ が閾値を超えた組だけ買う。閾値とオッズ上限は、前半の期間で決めて後半の期間で確認する。

## 構成
| パス | 役割 |
|---|---|
| `boatpred/download.py` | 公式の番組表(B)・競走成績(K)LZHを取得 |
| `boatpred/parse.py` | B/Kテキストのパーサ |
| `boatpred/web.py` | boatrace.jp から3連単オッズ・直前情報を取得 |
| `boatpred/features.py` | 特徴量(過去成績は前日までの集計のみ) |
| `boatpred/model.py` | 1着モデル・3連単確率・市場ブレンド |
| `boatpred/live.py` | 当日のループ(締切約7分前に確定予想)・仮想収支の確定 |
| `scripts/backtest.py` | 時系列のバックテスト |
| `scripts/train.py` | 本番モデルの学習 → `models/` |
| `site/index.html` | 予想ページ(GitHub Pages / gh-pages ブランチ) |

## GitHub Actions
- `train`(週1回・手動実行可): 不足データの取得 → 学習 → `models/` と `reports/` をコミット。**最初に1回手動で実行する**
- `live`(08:20 / 14:10 / 20:00 JST開始): 予想を出して gh-pages に公開する
- `nightly`(01:30 JST): 前日の結果と締切時オッズを取得し、仮想収支を確定する

データ(`data/`)は Actions のキャッシュに置く(消えても再取得できる)。

## 既知の限界(要検証)
- バックテストは「締切時オッズ」を使うが、本番は「締切数分前のオッズ」で判断するため、バックテストより成績が悪くなる可能性がある
- 学習時の進入は実際の進入で、本番はスタート展示の進入。前付けなどで両者がずれるレースでは差が出る
- 風向は、直前情報の表記と成績の表記の対応がまだ確認できていないため、特徴量から外している
- 同着・返還は簡略化して扱っている
